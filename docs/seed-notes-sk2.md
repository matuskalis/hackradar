# Research notes: Slovakia hackathons (seed-sk2)

## IMPORTANT CAVEAT UP FRONT
This session's `WebSearch` tool had already exhausted its budget (200/200) before I could issue a single query — every WebSearch call failed immediately. I fell back to `WebFetch` on search-engine URLs directly. Brave (`search.brave.com`) worked for a handful of queries early on, then started returning HTTP 429 for the rest of the session (many retries at increasing intervals never recovered). I then tried, and failed to get usable results from: Bing (returns geographically-irrelevant cached content regardless of query — Croatia/Malaysia/Walmart results for Slovak queries), Google (hard consent redirect loop, `gl=SK` forced by IP geolocation regardless of override params), DuckDuckGo/html.duckduckgo.com/lite.duckduckgo.com (CAPTCHA wall), Yandex (CAPTCHA), Yahoo (500 error), Ecosia/Mojeek/Startpage/Qwant/Swisscows (403, JS-only, or tool-level "unable to fetch"), 4get.ca and two SearXNG instances (429 or bot-IQ-test wall), etools.ch (refused as "crawler"), marginalia (near-empty index for these queries). Net effect: for roughly 90% of this session I had **no working search engine** and had to navigate to organiser/news sites directly by guessing URLs, which is why the yield below is much smaller than the 25+ target despite a very large number of attempts (150+ fetches).

Given the instruction to never fabricate a date or fill a row from a snippet alone, I only kept rows I could confirm by opening an actual page. I would need another session with working web search to get this Slovak dataset to 25+ rows properly.
